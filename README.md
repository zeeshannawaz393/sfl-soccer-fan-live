# SFL — Soccer Fan Live

A football-themed live-streaming & social mobile app concept ("The Living Stadium" direction, Niki Live / BIGO-inspired). This repo holds the full design system, all journey mockups, and an interactive click-through prototype.

## What's here

| Path | Contents |
|---|---|
| `design-direction.md` | The overall design direction & product concept |
| `journeys/` | Per-journey review docs (spec condensation + flagged conflicts / regulatory notes) |
| `screens/*.dev.html` | Editable source mockups — one file per journey (390×844 phone frames) |
| `screens/create-club.dev.html` | Create-a-Club flow (generated by `build/gen_createclub.py`) |
| `screens/sfl-prototype.html` | **The interactive prototype** — a single self-contained click-through player over every screen |
| `screens/sfl-all-screens-flat.html` | Flat single-page export of all screens (for Figma / HTML-to-design import) |
| `screens/assets/` | Imagery + embedded Manrope variable font |
| `build/` | Python build scripts that assemble the prototype & flat page from the `.dev.html` sources |

## The prototype

`screens/sfl-prototype.html` is a fully self-contained (font + images base64-inlined, no external requests) click-through prototype:

- A **☰ menu** (top-left) opens a modal to jump between curated **flows** (First-time fan, Start a club, Daily tasks, …) and **all journeys**.
- Tap **buttons, cards, tabs, and the phone's bottom nav** to move like a real app; **‹ Back / Next ›** to step.
- **◐** toggles light/dark.
- Responsive — works on desktop and phone.

Open it directly in a browser, or serve the folder:

```bash
python3 -m http.server 8770 --directory screens
# then open http://localhost:8770/sfl-prototype.html
```

## Rebuilding

The prototype and flat page are generated from the `.dev.html` sources:

```bash
python3 build/build_proto.py   # -> screens/sfl-prototype.html
python3 build/build_flat.py    # -> screens/sfl-all-screens-flat.html
python3 build/gen_createclub.py # -> screens/create-club.dev.html
```

> Note: the build scripts currently use absolute paths from the authoring machine — adjust the paths at the top of each script before running elsewhere.

## Model notes (concept stage)

- **One club at a time** — a user is fan/manager of exactly one club; a manager is also a fan of that club; can explore others read-only.
- **Currencies** — Coins (purchasable) vs Gold (earned, withdrawable).
- **Room types** — Formation/Squad rooms (multi-fan), Single-host rooms, PK Battles (two competing sides), Watch Parties (co-watch).
- Flagged regulatory considerations (gambling-adjacent loops, e-money/KYC/AML, licensing for real teams) are noted in the per-journey review docs — this is a **concept-stage** design, not a shipped product.
